## 1. Project Title
**AI-Based Skin Disease Detection and Severity Prediction using Deep Learning**

---

## 2. Abstract
Dermatological pathologies account for a substantial portion of global outpatient consultations. Early, non-invasive computational assessment of cutaneous lesions holds promise for assisting healthcare professionals and students in identifying conditions. This project presents **DermaVision AI**, a full-stack, explainable computer vision framework built with **EfficientNetB0 Transfer Learning**, a dedicated dual-branch inference pipeline (Disease and Severity), and **Grad-CAM (Gradient-weighted Class Activation Mapping)** for transparent anatomical visual attribution. Integrated into a responsive Flask web application backed by SQLite and Chart.js, the system provides real-time image validation, multi-class condition estimation, and audit logging.

---

## 3. Problem Statement
Traditional dermatological diagnosis relies heavily on physical visual inspection by experienced dermatologists. In resource-constrained environments, patients face extensive delays in accessing specialist evaluations. Existing automated diagnostic attempts frequently suffer from three critical flaws:
1. **Opaque "Black-Box" Behavior**: Providing raw predictions without explainable visual localization.
2. **Category-to-Severity Conflation**: Incorrectly assuming disease category equals condition severity.
3. **Data Fabrication**: Synthesizing clinical metrics or presenting mock diagnostics without rigorous dataset validation.

---

## 4. Objectives
- Implement an **EfficientNetB0** transfer-learning pipeline for 7 target dermatological disease categories.
- Design an isolated, dedicated secondary branch for **3-class severity grading** (*Mild*, *Moderate*, *Severe*).
- Integrate **Grad-CAM** to generate spatial activation heatmaps highlighting discriminatory lesion boundaries.
- Develop a full-stack web application (Flask + Bootstrap 5 + Chart.js) with local SQLite audit persistence.
- Enforce strict security, input validation, and medical safety disclaimers across all endpoints.

---

## 5. Proposed System
DermaVision AI implements a modular, client-server web architecture:
- **Client Tier**: Modern responsive UI with drag-and-drop ingestion, live image previews, Dark/Light modes, and interactive Chart.js probability breakdowns.
- **Application Tier**: Flask backend with secure file validation, MIME verification, dimension checks, and unified REST API (`POST /predict`).
- **Inference Tier**: Preprocessed tensor pipeline feeding into TensorFlow/Keras EfficientNetB0 models and OpenCV-based Grad-CAM heatmap blending.
- **Persistence Tier**: SQLite database managed through SQLAlchemy ORM, logging prediction histories without collecting personal identifying information.

## 9. Disease Classes (7 Target Classes)
1. **Acne Vulgaris** (`acne`): Inflammatory comedones, papules, and pustules.
2. **Eczema / Atopic Dermatitis** (`eczema`): Pruritic, erythematous scaly plaques.
3. **Fungal Infection / Tinea** (`fungal_infection`): Annular erythematous lesions with active scaly borders.
4. **Healthy / Normal Skin** (`healthy`): Normal skin tissue serving as negative control.
5. **Impetigo** (`impetigo`): Contagious superficial bacterial infection with honey-colored crusts.
6. **Psoriasis** (`psoriasis`): Chronic autoimmune plaques covered in thick silvery-white scales.
7. **Rosacea** (`rosacea`): Facial vascular erythema, telangiectasia, and flushing.

---

## 10. Severity Classes (3 Target Classes)
- **Mild** (`mild`): Low lesion count, minimal erythema, localized involvement.
- **Moderate** (`moderate`): Widespread involvement, prominent inflammatory papules/plaques.
- **Severe** (`severe`): Confluent extensive plaques, deep cystic lesions, or substantial barrier disruption.

> *Note*: Disease category datasets do not contain severity labels. The severity pipeline is trained independently only when clinician-annotated severity ratings are provided in `severity_dataset/`.

---

## 11. Data Preprocessing
1. **File Type & Header Verification**: PIL image stream decoding and format check (`.jpg`, `.jpeg`, `.png`, `.webp`).
2. **Dimension Constraints**: Minimum $50 \times 50\text{px}$, maximum $6000 \times 6000\text{px}$.
3. **Color Space Standardization**: Forced conversion to 3-channel RGB.
4. **Resampling**: High-quality Lanczos bicubic resizing to $224 \times 224$ pixels.
5. **Pixel Scaling**: Normalized to float32 values in $[0.0, 1.0]$.
6. **Batch Expansion**: Reshaped to $(1, 224, 224, 3)$.

---

## 12. Model Architecture
- **Backbone**: EfficientNetB0 (ImageNet pretrained weights, compound scaled feature extractor).
- **Data Augmentation Layers**: Random horizontal/vertical flip, random rotation ($0.2$), random zoom ($0.15$), random contrast ($0.15$).
- **Classification Head**:
  - GlobalAveragePooling2D
  - Batch Normalization
  - Dropout ($p = 0.35$)
  - Dense Layer ($256$ units, ReLU activation)
  - Batch Normalization
  - Dropout ($p = 0.25$)
  - Output Dense Layer ($7$ units, Softmax activation)

---

## 13. Training Procedure
```bash
python training/train_disease.py --epochs 25 --batch-size 32 --learning-rate 0.0001
```
- **Loss Function**: Sparse Categorical Crossentropy.
- **Class Imbalance Mitigation**: Inverse class frequency weighting:
  $$\text{weight}_c = \frac{N_{\text{total}}}{C \times N_c}$$
- **Optimizer**: Adam ($\alpha = 10^{-4}$).
- **Callbacks**: `EarlyStopping` (patience=6), `ReduceLROnPlateau` (factor=0.5, patience=3), `ModelCheckpoint` (best validation accuracy), `CSVLogger`.

## 15. Grad-CAM Explanation
Grad-CAM computes the gradient of the predicted class score $y^c$ with respect to the feature activation maps $A^k$ of the final convolutional layer (`top_conv`):
$$\alpha_k^c = \frac{1}{Z} \sum_{i} \sum_{j} \frac{\partial y^c}{\partial A_{i,j}^k}, \quad L_{\text{Grad-CAM}}^c = \text{ReLU}\left(\sum_k \alpha_k^c A^k\right)$$
The activation map is upsampled to the original image dimensions, color-mapped with OpenCV `COLORMAP_JET`, and blended onto the input image at $\alpha = 0.4$ opacity.

## 16. Flask Architecture
The Flask application (`app.py`) utilizes the Application Factory pattern:
- **Routes**:
  - `GET /`: Overview, status, taxonomy, and methodology summary.
  - `GET, POST /detect`: Image ingestion, validation, and multi-stage analysis execution.
  - `POST /predict`: REST API returning standardized JSON prediction structures.
  - `GET /result/<id>`: Result dashboard with side-by-side Grad-CAM and Chart.js probability bars.
  - `GET /history`: Interactive SQLite history log with search, disease filtering, and sorting.
  - `GET /about`: Academic documentation and ethical constraints.
  - `GET /api/health`: Health monitoring endpoint.
  - `GET /api/dataset-status`: Dataset scanner report.
